The 3.3 release of Agroal is a maintenance release with bug fixes and some new features, including an improved flush behavior when there are validation failures.

A special thanks to Eugene N, Wu Shuwen and Federico Mariani for their contributions.


## Bug
 
* [AG-315](https://redhat.atlassian.net/browse/AG-315) Collaborative connection creation in handlerFromSharedCache() pins virtual thread carriers, causing CPU spikes and livelock

* [AG-320](https://redhat.atlassian.net/browse/AG-320) Busy-spin in ConnectionPool.handlerFromSharedCache when the pool is below max-size and connection creation is slow

* [AG-322](https://redhat.atlassian.net/browse/AG-322) Stale pool handling (AG-302) opens connections without bound when the pool is busy
  
* [AG-323](https://redhat.atlassian.net/browse/AG-323) AgroalPropertiesReader truncates JDBC/XA property values containing equals signs

## Enhancement
   
* [AG-316](https://redhat.atlassian.net/browse/AG-316) Introduce agroal-bom
                             
* [AG-317](https://redhat.atlassian.net/browse/AG-317) Support Request Boundaries 
                                                    
* [AG-319](https://redhat.atlassian.net/browse/AG-319) Optimize dependencies of agroal-spring-boot-starter
                                                  
* [AG-324](https://redhat.atlassian.net/browse/AG-324) Add validationFailureFlushThreshold to configure when a failed validation flushes the pool
